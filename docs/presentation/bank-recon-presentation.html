1. 담당자와 사용 목적

운영팀 대조 담당 지우의 하루

지우는 매일 아침 전날 거래를 대조합니다. 짝 맞추기는 엑셀 매크로가 하지만, 남은 건을 끝까지 쫓는 일에 시간이 가장 많이 듭니다.

지금 하는 방식 (앱 도입 전)

① 내역 받기시스템 거래내역과 은행 통장 내역을 내려받음
② 엑셀 매크로같은 거래끼리 자동으로 짝 맞추기
③ 출력물 체크남은 시스템 내역을 출력해 손으로 하나씩 체크
④ 잔액 비교시스템 잔액 vs 통장 잔액. 차이 0원이면 끝
⑤ 통합 메일안 맞으면 전 부서에 메일을 직접 써서 보고

불편한 점

  • 남은 건이 메일과 출력물에 흩어져, 며칠 지나면 무엇이 남았는지 추적이 어려움
  • 누가 처리해야 하는지, 어느 팀장에게 보고할지 매번 직접 정리
  • 가장 흔한 문제는 시스템 미반영: 돈은 통장에 들어왔는데 담당자가 시스템에 반영하지 않음
  • 감사 때 "누가 언제 무엇을 고쳤나"를 증명하기 어려움

앱으로 바뀌는 점 (사용 목적)

  • 남은 건만 미대조 항목으로 등록 → 한 목록에서 경과일·긴급도와 함께 추적
  • 처리 담당과 보고 대상 팀장, 보고 문구를 자동 작성
  • 차이 0원 + 남은 항목 0건이면 자동 완료
  • 완료 후 잠금 + 변경 이력으로 감사 증거가 남음

1. 함께 일하는 사람

앱은 운영팀만 쓰고, 다른 부서는 메일로 받습니다

실제 업무 방식(통합 메일 보고 → 각 부서 처리 → 운영팀 확인)을 그대로 따랐습니다. 다른 부서 사람들은 앱에 들어오지 않고 처리 담당·보고 대상으로 이름만 기록됩니다.

사람 부서 · 직책 앱에서의 역할 앱 접근 예시

도윤 재무팀 · 시스템 반영 담당 처리 담당 (이름만) 없음 RI-0007 한별물산 5,000,000원을 시스템에 반영

서아 / 유진 기업금융팀 담당 / 팀장 처리 담당 / 보고 대상 없음 입금자명이 다른 기업 고객 건 확인

처리 담당과 보고 대상은 로그인 사용자(User)가 아니라 직원(Employee) 기록을 가리킵니다. 그래서 앱 권한이 없는 부서도 담당자로 기록할 수 있습니다.

실선 박스 새로 만든 오브젝트   점선 박스 기존 오브젝트 재사용   굵은 선 = 주종 관계, 가는 선 = 참조(Lookup)

입출금 대조 관리 앱5
2. 데이터 모델링 · 특히 신경 쓴 부분 ①

무엇을 저장하고, 어디에 두고, 무엇을 참조할까

설계에서 가장 먼저 정한 것은 "모든 거래가 아니라 안 맞는 건만 저장한다"입니다.

결정 이유 버린 대안
안 맞는 건만 저장 짝 맞추기는 엑셀 매크로가 이미 잘함. 관리가 필요한 건 남은 예외뿐. 하루 수백 건을 넣지 않아 데이터와 입력 부담이 작음 모든 거래를 한 오브젝트에 넣고 앱에서 짝 맞추기
대조와 항목을 두 오브젝트로 분리 잔액·상태는 하루 한 번, 항목은 여러 건. 한 오브젝트에 두면 잔액이 항목마다 중복됨 항목 오브젝트 하나에 잔액까지 기록
주종 관계 (Master-Detail) 남은 항목 수를 롤업으로 자동 집계 → Flow가 완료를 판정. 항목의 공개 범위도 대조를 그대로 따라감 (운영팀만) 참조(Lookup): 롤업 불가, 보안을 따로 설정해야 함
거래처는 Account 재사용 기업 고객은 은행의 거래처이므로 이미 있는 Account가 맞는 자리. "기업/은행" 구분 칸만 추가 거래처 오브젝트를 새로 만들기 (중복)
담당자는 Employee 참조 (User 아님) 처리 담당은 앱 권한이 없는 다른 부서 사람. 로그인 사용자가 아니어도 기록되고, 직원의 상사를 따라 보고 대상 팀장이 자동으로 나옴 User 참조: 다른 부서에도 라이선스와 권한 필요
계좌는 Picklist (체킹/패런트) 계좌가 2개로 고정. 저장 값은 짧게, 화면 표시는 "패런트 (기업 고객 모계좌)"처럼 설명을 붙임 계좌 오브젝트 만들기 (과한 구조)

2. 데이터 모델링 · 특히 신경 쓴 부분 ②

필드 타입: 사람이 넣을 값과 시스템이 계산할 값을 나눴습니다

사람이 입력하는 칸은 최소로 두고, 계산할 수 있는 값은 모두 수식·롤업·Flow로 만들었습니다. 계산 값은 사람이 고칠 수 없어서 틀릴 일이 없습니다.

필드 타입 왜 이 타입인가
시스템 잔액 · 통장 잔액 · 금액 통화, 소수점 0자리 원화(KRW)는 소수점이 없음. 통장 잔액은 비워 둘 수 있게 해서 "아직 모름(진행 중)"을 표현
차이 수식 (저장 안 함) 통장 잔액 − 시스템 잔액. 잔액을 고치면 즉시 다시 계산되어 항상 맞음. 통장 잔액이 없으면 빈칸
남은 항목 수 롤업 (조건: 미해결) 해결 체크하면 자동으로 줄어듦 → 완료 판정의 기준
긴급 목적 미해결 수 롤업 (조건: 지급 대행 자금) 대조 단위 긴급 깃발에 사용
상태 Picklist + Flow 자동 설정 진행 중 / 보고 필요 / 완료. 사람이 고르지 않고 규칙대로 판정
보고 내용 긴 텍스트 (Flow 작성) 미해결 항목마다 한 줄씩, 메일에 그대로 붙여 넣을 수 있는 문구
보고 대상 · 보고 부서 수식 (다른 오브젝트 참조) 처리 담당 → 직원 → 상사의 직책·이름. 조직이 바뀌어도 자동으로 따라감
경과일 수식 오늘 − 대조일. 해결되면 빈칸, 음수는 0으로
긴급도 수식 (이미지 깃발) 긴급 지급 대행 자금 또는 3일 이상  보통  해결
원인 · 입금 목적 · 거래 유형 Picklist 자유 입력이면 집계가 안 됨. 고정 값이라 "원인별 통계"가 가능 (시스템 미반영이 가장 많음)

3. 자동화 구성

Flow 2개 + 기록 보호 규칙 4개

사람은 잔액과 안 맞는 건만 입력합니다. 판정, 보고 문구, 보고 대상, 잠금은 자동입니다.

Flow ① 일일 대조 상태 판정 (레코드 트리거, 저장 직전)

조건 결과
통장 잔액 없음 진행 중
차이 0원 + 남은 항목 0건 완료
그 외 보고 필요 + 보고 내용 자동 작성 (항목마다 "처리 담당 → 보고 팀장") + 보고 일시

항목을 해결 체크하면 롤업이 바뀌면서 대조가 다시 저장되고, 판정도 다시 실행됩니다.

Flow ② 대조 입력 마법사 (스크린 Flow, 홈 화면)

  1. 새 대조 만들기 / 진행 중인 대조 이어서 하기
  2. 잔액 입력 (이어서 할 때는 기존 값이 채워짐)
  3. 차이가 있으면 "안 맞는 금액을 등록할까요?"
  4. 항목 등록 (여러 건 반복)
  5. 결과: 상태 · 차이 · 남은 항목 · 보고 대상 · 대조 화면 링크

기록 보호 (검증 규칙)

  • 처리 사유 없이 해결 체크 불가
  • 완료된 대조의 날짜·계좌·잔액 수정 불가 (관리자도)
  • 완료된 대조에 항목 추가 불가
  • 해결된 항목의 금액 수정 불가

Agentforce는 이번 범위에서 구현하지 않았습니다. 다음 단계 후보: "오늘 긴급 건 정리해 줘", "도윤에게 보낼 확인 메일 초안 써 줘" 같은 업무 위임.

3. 시연 ① 레코드 예시: DR-0005 (10/14 패런트)

# 하는 일 화면에서 확인할 결과
1 홈 화면 열기 현황 카드: 긴급 항목·보고 필요 건수, 확인 필요 목록에 DR-0005 긴급
2 DR-0005 열기 자동 작성된 보고 내용:
1. 한별물산 입금 5,000,000원 - 시스템 미반영 (처리 담당: 도윤 → 보고: 재무팀장 태오)
2. 블루웨이브 로지스틱스 입금 10,000원 - 금액 다름(수수료) (처리 담당: 지우 → 보고: 운영팀장 하린)
3 RI-0007 (한별물산, 지급 대행 자금)에서 처리 사유 없이 해결 체크 저장이 막힘: "해결 체크를 하려면 처리 사유를 입력하세요"
4 처리 사유 "재무팀 시스템 반영 완료" 입력 후 저장 깃발 해결, DR-0005 남은 항목 1건, 보고 내용이 1줄로 줄어듦
5 RI-0008 (수수료 10,000원)도 처리 사유 입력 후 해결 남은 항목 0건. 차이는 아직 있으므로 계속 보고 필요
6 DR-0005 시스템 잔액을 2,244,990,000원으로 정정 차이 0원 → 상태 완료
7 완료된 DR-0005의 잔액을 다시 바꿔 보기 저장이 막힘: "완료된 대조는 대조일, 계좌, 잔액을 고칠 수 없습니다". 화면 아래 변경 내역에 누가 언제 무엇을 바꿨는지 남아 있음

7번 이후에는 DR-0005가 잠깁니다. 리허설 후 되돌리려면 해결 체크를 먼저 풀고(상태가 보고 필요로 돌아감) 잔액을 2,240,000,000원으로 되돌립니다.

4. 처음 보는 사람이 물어볼 만한 것

예상 질문과 답

만든 사람에게는 당연하지만 처음 보는 사람에게는 당연하지 않은 부분입니다.

질문 답
왜 모든 거래를 넣지 않나요? 짝 맞추기는 엑셀이 이미 하고 있습니다. 매일 수백 건을 다시 입력하면 일이 늘어납니다. 관리가 필요한 건 남은 예외입니다.
해결 체크를 다 했는데 왜 완료가 안 되나요? 시스템 잔액도 정정해야 차이가 0원이 됩니다. 잔액을 자동으로 고치지 않은 이유는, 실제 장부에 반영됐는지는 사람이 확인해야 하기 때문입니다.
재무팀은 처리 상황을 어떻게 아나요? 자동 작성된 보고 내용을 메일로 받습니다. 대조 기록은 운영팀만 볼 수 있습니다 (예전 통합 메일 방식과 같음).
잔액을 잘못 넣었는데 완료돼 버리면요? 완료 후에는 잠깁니다. 꼭 고쳐야 하면 관리자가 "대조 수정 예외" 권한을 잠시 주고 고치며, 그 내용은 변경 이력에 남습니다.
처리 담당은 왜 사용자(User)가 아니라 직원인가요? 다른 부서는 앱 권한이 없습니다. 직원 기록이면 권한 없이도 담당자로 기록되고, 상사를 따라 보고 대상 팀장이 자동으로 나옵니다.
같은 날 같은 계좌를 두 번 만들면요? 지금은 막지 않습니다. 하루 × 계좌당 1건을 원칙으로 하고, 중복 방지 규칙은 다음 과제입니다.
입력이 많지 않나요? 남은 건만 입력하지만 패런트 계좌는 건수가 많습니다. 다음 단계로 엑셀 결과를 CSV로 한 번에 올리는 기능을 생각하고 있습니다.

4. 팀원 산출물 리뷰 · 다음 단계

다른 팀에 던질 질문 틀과 이 앱의 다음 단계

"하나의 시스템에서 모두가 일한다"는 관점으로, 다른 팀 산출물을 볼 때 이 다섯 가지를 물어보려고 합니다.

팀원 산출물에 할 질문 5가지

  1. 사용자: 매일 이 앱을 여는 사람은 누구이고, 한 건 처리에 몇 번 클릭하나요?
  2. 입력: 사람이 꼭 넣어야 하는 칸과 자동으로 채울 수 있는 칸이 나뉘어 있나요?
  3. 예외: 값이 비거나 잘못 들어오면 어떻게 되나요? 중복은 막히나요?
  4. 권한: 이 데이터를 보면 안 되는 사람은 누구이고, 실제로 막혀 있나요?
  5. 자동화: Flow가 실패하거나 조건에 안 맞으면 누가 알아차리나요?

현업 적용 가능성

짝 맞추기는 기존 도구에 맡기고, 시간이 가장 많이 드는 남은 건의 추적·보고·감사 기록을 자동화했습니다. 엑셀과 출력물로 대조하는 작은 지점·운영팀에 현실적입니다. 큰 은행은 대사 전용 솔루션을 쓰고, 금융권 클라우드 규정 검토가 필요합니다.
